# How to verify the changes

## Quick way: one command

```bash
./setup.sh                          # once
BLEND_DIR=../BLEnD ./test_all.sh    # about 3 minutes, no API keys needed
```

Expected: **`43 passed, 0 failed, 1 warnings`**. The warning is the skipped real-API test;
`./test_all.sh --api` runs that one too, if `OPENAI_API_KEY` / `GEMINI_API_KEY` are set.
The script works in a temporary copy, so this folder is never modified. It writes a
report to `test_report.md`.

| Section | What it checks |
|---|---|
| 1. Environment | Python, packages, `hazm==0.10.0`, spaCy model |
| 2. BLEnD data | the BLEnD folder, the pinned commit and the 6 data files |
| 3. Pipeline | deletes all derived files, re-runs every step, and compares each regenerated table/summary byte-for-byte with the delivered one |
| 4. pytest | scorer unit tests and every number on poster v7 |
| 5. Legacy vs new | runs the **old** scorers from `legacy/` and compares every item score with the new scorer (3,700 items) |
| 6. Inference | the resumable API loop, using a fake model |
| 7. Manual sample | the validation sample (50 = 25 + 25) and the error-analysis sheets |

The test catches real bugs. As a check, the empty-answer guard was deliberately removed
from `blend/scoring.py`: 6 checks then failed, each naming question `New-gr-08`.

The sections below do the same checks by hand.

Everything below runs locally without API keys.

## 0. Setup (once)

```bash
cd blend-crosslingual
python -m venv .venv && source .venv/bin/activate      # optional
./setup.sh           # requirements + hazm 0.10.0 + spaCy English model
```

If BLEnD already exists elsewhere (for example `../BLEnD`), use `export BLEND_DIR=../BLEnD`.
Otherwise `run_all.sh` clones it into `external/BLEnD` at the pinned commit.

## 1. The pipeline rebuilds all results from the raw responses

First take a snapshot of the delivered files. `git add` only stages them in the git index;
it does **not** create a commit:

```bash
git init -q && git add -A        # snapshot, no commit
./run_all.sh
git diff --stat                  # files changed by the run
```

(`git status` is not useful here: without a commit it marks every file as `A`/new.)

Expected: `git diff --stat` lists **no `.csv` or `.md` file**. All tables and summaries are
regenerated byte-for-byte from `results/*/raw/*.jsonl`. If one shows up as modified, inspect
it with `git diff`.

Figure files (`results/figures/*.png|pdf`) may show as modified. That only means your
matplotlib version renders pixels slightly differently. With one matplotlib version the
output is identical on every run. Open them to check visually, then restore the delivered
versions with `git checkout results/figures`.

## 2. The numbers match poster v7

```bash
pytest -q
```

Expected: `57 passed`. `tests/test_reproduce.py` compares every number printed on poster v7
with the new output:
- accuracies, n and McNemar p for all 4 settings
- GEE χ² and p for all 4 settings
- domain gaps for Food and Holidays
- Persian reviewer agreement and kappa
- the Education value that the v7 figure plotted wrongly

`tests/test_scoring.py` checks the scorer rules:
- empty reference answers
- local answers checked before English
- Persian matching
- first-answer splitting

## 3. The new scorer gives the same scores as the old scripts

```bash
python -m blend.score
python - <<'PY'
import pandas as pd
for country, lang in [("Azerbaijan", "Azerbaijani"), ("Iran", "Persian")]:
    for m in ["gpt-4.1", "gemini-3.5-flash-lite"]:
        for l in ["English", lang]:
            new = pd.read_csv(f"results/{country}/scored/{m}_{l}.csv")
            new = new[new.valid]
            print(f"{country:10s} {m:22s} {l:12s} SEM-B = {100 * new.binary_score.mean():.1f}")
PY
```

Expected, identical to poster v7:

| | GPT-4.1 EN | GPT-4.1 local | Gemini EN | Gemini local |
|---|---|---|---|---|
| Azerbaijan | 70.6 | 69.7 | 56.1 | 65.7 |
| Iran | 69.7 | 73.7 | 57.7 | 65.1 |

To run the **old** scripts yourself, `legacy/` holds them unchanged.
- **Azerbaijan:** copy `legacy/azerbaijan_src/*.py` into a `src/` folder next to `third_party/` and `results/raw/`, then run `python src/score.py`.
- **Iran:** run `python legacy/iran_pilot/score_iran_pilot.py` from a folder that has `BLEnD/` and `results/iran_pilot/raw/`.

## 4. Look at the new outputs

- `results/comparison/summary.md`: all poster numbers. It starts with the sensitivity table (official = primary, strict = sensitivity), which shows which conclusions are robust
- `results/manual/validation_summary.md`: reviewer kappa, and automatic scoring vs human judgment
- `results/manual/validation_summary.md`: both settings have 2 independent reviewers (with kappa)
- `results/figures/`: fig1 to fig4, as PDF and PNG
- `results/comparison/response_language.csv`: in which language or script the models answer local-language prompts
- `results/manual/<Country>/error_analysis_candidates.csv`: all questions answered correctly in only one language, for picking poster examples

## 5. Pinned versions that matter

- `hazm==0.10.0`: with hazm 0.9.x, `pytest` **fails** on Iran/Gemini (65.6 instead of 65.1). This failure is expected and is the reason the version is pinned.
- BLEnD commit `7b9c131`: `run_all.sh` checks it out.
